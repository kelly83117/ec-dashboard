> 🔴 **防護碼本體只有一份權威版本，在 [`docs/PChome淨利表_開發交接.md`](PChome淨利表_開發交接.md) §0。這份文件不再放程式碼本體。**
> 為什麼不複製一份過來：本 repo 已實際踩過防護碼漂移——舊版預期值「4 物件 / 9 方法」，但雲端物件早已長到 **17 個 / 25 方法**（`__cloudCostByOrigin`、酷澎三個、`__cloudAff`、`__cloudTaskImage` 等後來加的都沒被舊版擋到）。**兩份會漂移的副本＝有人拿舊版去測、漏擋新物件、寫壞正式資料。** 所以本體只留 §0 一份，這裡只講「什麼時候用／貼在哪／怎麼確認／怎麼拆除」。
>
> 要測時：複製 §0 的那段（兩層：動態掃描 no-op ＋ MUST 明列 17 物件；物件數會隨新增而變、**當場重數**），照下面步驟操作。

### 什麼時候要用

只要妳要**在本機起 server 開 App**，不管只是看看還是要測功能，**都先貼**。

### 貼在哪（位置很關鍵，貼錯等於沒貼）

貼進 **`js/firebase.js`**，位置是：

- 在 `window.__cloudInsight` 這個物件結尾的 `};` **之後**
- 在 `window.dispatchEvent(new Event('cloudStoreReady'));` 這行 **之前**

用這兩個錨點找位置，**不要記行號**。

**為什麼一定要在這個位置**（兩個條件缺一不可）：

1. 所有 cloud 物件都定義完了 → 檢查才找得到全部。
2. 在 dispatch 之前 → 如果 throw，`cloudStoreReady` 不會觸發 → `__setupCloud` 永遠不跑 → `Store.set` 永遠不被 patch → **零雲端寫入**。

> ⚠️ **不能貼在 F12 主控台。** `Store.set` 的 patch 閉包捕獲了原本的物件，事後在 Console 換掉 `window.__cloudStore` 擋不掉。必須貼進檔案裡的那個位置。

### 程式碼本體

**不放在這裡**——複製 [`docs/PChome淨利表_開發交接.md`](PChome淨利表_開發交接.md) §0 的那段（唯一權威版本）。貼進上面「貼在哪」講的位置即可。

### 怎麼確認它真的生效（開 App 第一件事就看 F12 Console）

| 妳看到 | 意思 | 該做什麼 |
|---|---|---|
| 紅字 `[TEST_NOWRITE] 已停用雲端寫入：N 物件 / M 方法`，數字跟**當下實際的物件數**相符 | ✅ 保護生效 | 可以放心測 |
| 沒有紅字，但畫面有熟悉的數字 | 🔴 **保護沒跑，妳正在寫正式庫** | **立刻關分頁** |
| 沒有紅字，畫面是空的 | firebase init 失敗 | 安全，但要查為什麼 |
| 有紅字但數字對不上預期 | 有東西沒擋到，或系統新增了 cloud 物件 | **停下來查，不要因為比預期多就當沒事** |

**throw 之後畫面不是白的。** throw 會被 firebase.js 的 catch 接住 → Console 印 `Firebase init failed: [TEST_NOWRITE]…` → app.js 的 5 秒 fallback 用**純 localStorage 模式**開起來（畫面出得來，但沒有雲端資料）。這是刻意設計的 fail-loud。

### 測完怎麼拆除（順序錯了有地雷）

**一定照這個順序：**

1. **先關掉本機那個分頁**
2. **再停掉 server**
3. **最後才刪掉 `js/firebase.js` 裡那整個區塊**

反過來的話，會出現「檔案已經沒有保護、但瀏覽器記憶體還是舊的」——這時候重新整理一下，就直接寫正式庫了。

**刪除方式：手動編輯刪掉整個區塊。**

- ❌ 不要用 `git checkout js/firebase.js`（會洗掉同一次改動裡的其他東西）
- 刪完跑 `git diff js/firebase.js`，**應該是空的**
- commit 時只 `git add` 妳真正改的檔案，**不要 `git add -A`**，免得把測試碼夾帶上去

### 為什麼這段程式碼不能 commit 進專案

它的設計是「**非 localhost 就 throw**」。如果跟著上正式站，**全公司的 App 會直接開不起來**。所以它只能「用時貼、測完刪」，沒辦法變成專案的一部分給大家共用。

> 📌 根治的做法是改用獨立的 dev Firebase 專案（可以 commit、fail-safe），那是另一個獨立工程，還沒做。TEST_NOWRITE 是護欄，不是修復。

## 🖥️ 本機環境

隨便一個靜態 server 都可以（妳習慣哪個就用哪個）。要注意的只有這幾點：

- 網址一定用 **`localhost`**（例如 `http://localhost:8000`）。**不要用區網 IP**，系統的 host-check 只放行 localhost。
- 改完 code 一定**硬重整**（強制略過快取），不然會載到舊版。
- **本機和正式站是兩份完全獨立的登入和資料**，本機要妳重新登入是正常的，不是出錯。

## ⚠️ 費率輸入框有個雷

上傳檔案時那個可以手動調的費率——**它能用，但它不會記得。**

- HTML 寫死 `value="20.5"`，**重整就跳回**
- 報表存檔**有**把費率存進去，但**打開舊報表時不會還原輸入框**

**後果：**

> 今天設好、算完、存起來 → 明天重整 → 框框回到 20.5%

而且全站只有一個輸入框、四個通路共用。

## 其他該知道的

### localStorage 快滿了（還沒修）

一份好麻吉報表約 **0.92 MB**，有人的瀏覽器已經累積到 6.5 MB 以上。

**存不下的時候系統不會說**（空的 catch 吞掉）→ 畫面照樣顯示 → 關掉就永久消失。

→ **在修好之前，重要報表產完就按同步，別囤在本機。**

### 月份下拉會自己跳

當前月份沒資料時，系統會**自動切到「最新有資料的月份」**。

→ 很容易誤以為「這個月數字沒更新」，其實是「這個月根本沒上來」。

### 版本號要改 15 處（⚠️ 舊版寫 12 處，是錯的）

改任何檔案（含 CSS）都要 bump，**漏掉同事會拿到舊版**（快取 10 分鐘）：

- `index.html` 的 `<meta name="app-version">`
- `index.html` 的 `<script src="js/main.js?v=">` ← **最容易漏這個**
- `js/main.js` 裡 10 個 import 的 `?v=`
- **CSS 的 3 個 `?v=`** ← 舊版漏掉了這三個

**用 `bump-version.js` 跑，不要手動改。**

**不要憑記憶抓現在幾號**，直接去檔案裡搜 `app-version` 看現在的號。新版號要**比檔案裡的、也比 main 上的都大**（main 有時會回退，版本號不一定是遞增的，一定要當場確認）。

### 這個專案沒有建置流程

純手寫 HTML + CSS + 原生 JS，沒有 React/Vue、沒有 npm build。**不能引入需要編譯的語法。**

跨檔呼叫一律走 `window`（模組結尾要 `Object.assign(window, {…})` 掛回去）——**忘了掛，按鈕點下去會 ReferenceError 靜默失效。**

## 🔧 我踩出來的工作流程（照做會少走很多冤枉路）

1. **開工前一定 `git pull`**（main 很活躍，一天可能被推很多筆，而且還會回退）
2. **樣式一律寫進 `css/`，不要用 inline style**
3. **改完一定在瀏覽器實際點過再 commit**——「程式碼看起來對」跟「畫面上真的對」是兩回事，我在這裡撞過牆
4. **一次只做一塊**，做完驗過再做下一塊；不要一次改三個東西再一起驗，出事分不清是哪個
5. **push 前先防撞**：
   ```
   git fetch
   git log --oneline HEAD..origin/main
   ```
   有輸出代表 main 又被推了，**先 merge 再 push**
6. **用 merge，不要 rebase**（分支 push 過後 rebase 要 force push，風險不對等）
7. **push 完就直接開 PR、直接合併，中間不要跑去做別的事**——main 很活躍，拖越久越可能又要 merge 一次
